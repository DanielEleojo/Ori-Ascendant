# Lens: session-ux

## Summary
Research across idle-game design literature (Eric Guan, Mobile Free To Play, GameAnalytics/Adjust, thumb-zone ergonomics studies) converges on clear patterns: idle players average ~8-minute sessions with high stickiness (18% vs 10.5% for other casual games), and a 2-minute check-in is satisfying only if it contains at least one state change (collect, then an advance or visible threshold crossing) — while 20-minute sessions need a capstone arc (path choice deliberation or the tribulation push). Welcome-back screens follow a near-universal formula: time away, big animated earned number, production-rate context, one collect button — the "2x multiplier" variant exists solely to sell rewarded ads, so Ori Ascendant (no ads) should use a single one-tap Collect. Layout convention is equally settled: resource counter and rate in a top HUD (display-only, fine in the hard-to-reach zone), visual anchor in the middle, all interactive elements in the bottom-third green thumb zone per Hoober's research (75% of users are thumb-driven, 49% one-handed). Pure tap-to-earn is out of fashion, but a light, optional active mechanic is well-supported by Egg Inc-style designs; the recommended form — each tap grants 5 seconds of current production — reuses the existing rate formula, needs no timers, cooldowns, or save fields, and makes all three paths feel different even while tapping.

## Recommendations

### [high] MainScreen layout — exact top-to-bottom element list (portrait, single screen)
On iPhone 12-15 (390x844pt logical, 47pt top / 34pt bottom safe areas): (1) Header row at ~6-10% height: Generation badge left ('Gen 3'), settings gear right — low-frequency taps, acceptable in the red thumb zone. (2) Àṣẹ counter at ~10-20%: THE big number, top-center, largest text on screen (~52pt), suffix-abbreviated via BigNumber (1.24M), with '+12.4 Àṣẹ/s' rate line directly beneath at ~17pt. Display-only, so top placement costs nothing ergonomically. (3) Stage/path identity line at ~20-24%: 'Stage 4 — [name]' plus path icon once chosen. (4) Cultivator portrait at ~24-58%: the static per-stage art, with a slow ambient particle drift of Àṣẹ motes flowing into it so passive income reads as alive — research is explicit that returning to static numbers kills momentum. This is also the tap-to-channel target (yellow/green thumb zone, comfortable for repeated taps). (5) Stage progress bar at ~58-64%, directly under the portrait: fill = aseAmount/nextThreshold, label 'Next: Stage 5 — 45.2K / 100K'. (6) Primary CTA button at ~66-76% (dead center of the green thumb zone, full-width minus margins, >=50pt tall): 'Advance' when threshold met, morphs into a pulsing 'Face Tribulation' at stage 6 + 1M Àṣẹ. Disabled-but-visible otherwise so the goal is always on screen. (7) Ancestral Council strip at ~78-88%: five 56pt slots in a horizontal row, filled with ancestor icons (dimmed 0.4-style treatment for fallen ancestors), empty slots outlined — this is the prestige-visibility surface that makes gen 2 feel stronger at a glance. Nothing interactive below it (home indicator zone).

### [medium] Make stage advancement a manual button tap, not automatic
The locked design doesn't specify auto vs manual advancement. Recommend manual: a 2-minute check-in is only satisfying if it contains an action with a visible consequence, and 'tap Advance, watch the rate line jump from +12.4/s to +31.0/s' is exactly that moment. It also gives the CTA button (element 6) a reason to exist between tribulations and matches genre convention (Egg Inc, AdVenture Capitalist, Idle Miner all gate advancement/expansion behind a deliberate tap). Implementation is trivial: button enables when aseAmount >= threshold, fires OnStageAdvanced. Flag this to the orchestrator as a confirm-before-implement item since it touches progression flow (CLAUDE.md 'If Unsure' rule).

### [high] Welcome Back screen — flow and content
Trigger on cold start AND foreground-resume when elapsed >= 180 seconds (below that, silently add the Àṣẹ — quick app-switches must not spawn popups). Modal card over a dimmed MainScreen, top to bottom: (1) thematic header ('Your Ori kept watch'), (2) time-away line ('Away 6h 12m' — show '8h (cap)' when elapsed exceeded 28800s; honesty about the cap is important, players resent discovering hidden caps), (3) the earned Àṣẹ as a large count-up animation, 1.0-1.5s, tap-to-skip, (4) rate context line ('at 12.4 Àṣẹ/s') so the number teaches the player their own economy, (5) single full-width 'Collect' button bottom-center in the green thumb zone. Collect fires a particle burst, the number flies into the main counter, modal dismisses. Total flow under 3 seconds. No close-X and no alternate path — earnings are always collected, one button, zero decisions. Do NOT include a 2x-multiplier choice: that pattern exists exclusively to sell rewarded ads, which the MVP excludes; a multiplier without an ad just devalues the base number.

### [high] Include ONE trivial active mechanic: tap-to-channel (5 seconds of production per tap)
Verdict: yes, include it — but only in this form. Each tap on the cultivator portrait grants aseAmount += asePerSecond * TAP_CHANNEL_SECONDS (recommend 5.0, defined in a ScriptableObject per the no-magic-numbers rule). Why this exact shape: (a) one line of code in the existing Àṣẹ-grant path — no timers, no cooldown state, no new SaveData fields, no UI beyond a floating '+62' text and a brief portrait pulse + light haptic; (b) it reuses the full rate formula, so stage, path, and council bonuses all flow through automatically — tapping as Sango feels different from tapping as Osun, directly serving the 'paths feel meaningfully different in 10 minutes' PRD target; (c) at a comfortable ~2 taps/sec it yields ~10s of production per real second (~11x idle rate), naturally bounded by thumb fatigue — active play is clearly better without any cap logic; (d) it is strictly optional, satisfying 'never mandatory'. Research basis: pure tap-to-earn is 'out of fashion' and the no-tap simulation category is growing fastest, but Egg Inc demonstrates that a light optional tap makes short sessions feel participatory; timed boost buttons ('2x for 60s') are the common alternative but require cooldown persistence and timer UI — scope creep for a 5-feature MVP. If even this feels like creep, it is the single safest feature to cut, since nothing else depends on it.

### [high] Design the 2-minute and 20-minute sessions as distinct loops over the same screen
2-minute check-in script (must complete in under 10 taps): Welcome Back collect (1 tap, 3s) -> glance at big number and progress bar -> Advance if affordable (1 tap, rate visibly jumps) -> optional 20-30s of channel-tapping to crest a near threshold -> leave with the next goal visible on the progress bar. For this to work, early stage thresholds must be tuned so a typical 2-4h absence funds roughly one advancement in Tier 0 (the existing 1,000-to-Tier-1 placeholder at 1.0/s base = ~17 min idle for stages 0-2 combined, which is reasonable). 20-minute session script: an arc with a capstone — either the stage-2 path choice (present all three paths on one selection moment with explicit multiplier framing) or the Tier 1 push toward tribulation; the 60/40 tribulation coin-flip plus ancestor reveal IS the 20-minute payoff, and channel-tapping at ~11x idle means 20 active minutes ≈ 3-4 idle hours, making the long session feel earned rather than required. Per Eric Guan's cadence research, players self-select check-in frequency over time; the 8h offline cap plus one-advance-per-checkin pacing supports a 2x-3x daily cadence without punishing once-a-day players.

### [high] Feedback minimums that make passive progress feel alive (cheap, high-leverage)
Three items, all shippable in the MVP art budget: (1) the Àṣẹ counter ticks visibly every 1s tick rather than only on collect — a number that moves is the genre's core dopamine surface; (2) floating '+N' text on channel taps and a single particle burst on Collect/Advance/Tribulation outcomes — constant feedback per interaction is the most-repeated UI principle in clicker design literature; (3) light haptic (UIImpactFeedbackGenerator-light equivalent) on channel tap, medium on Advance, heavy on tribulation resolution. Skip everything else (screen shake, combo meters, idle animations) — static portrait + particles is enough.

### [high] Number formatting and counter behavior
Use suffix abbreviation (1.24K / 1.24M / 1.24B) with 3 significant digits everywhere — counter, progress label, welcome-back screen — never scientific notation in MVP (the BigNumber struct should expose a ToDisplayString()). Show the production rate ('+X/s') adjacent to the balance at all times: it is the player's single most important decision input (do I advance now? which path?) and every reference layout in the genre keeps resource + rate paired in the top HUD.

# Dynasty stories come from an authored, reviewed deck — never live generation

The per-player dynasty story is assembled from a library of authored,
folklore-rooted beats (events, figures, epithets) — each human-reviewed once under
the §7.10 native-speaker gate — and stitched into a unique Chronicle by each
player's choices and outcomes. Uniqueness comes from *combination and consequence*,
not from generating new prose per player.

We rejected free-form, live AI generation of folklore. ART_BIBLE §7.10 requires
every piece of cultural content to be human-reviewed *before* a player sees it, and
you cannot review what a model invents in real time — live-generated Yoruba/Igala
folklore is exactly what that red line exists to prevent. The cost we accept is
bounded, hand-authored content; the benefit is that every word ships pre-cleared.

## Consequences
- Content scales by authoring + review, not by model calls. The crossroads deck is
  a reviewed asset; contextual draw (by Stage, Ori, Path, dynasty) yields variety
  from a lean deck so review load stays bounded.
- No server-side generation dependency: the story layer works offline, fitting the
  idle, local-first design.
